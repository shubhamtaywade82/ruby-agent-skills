# Test quality: assertions, seams, and doubles

Reference for the `ruby-tdd-refactoring` skill. Load it on demand when writing or reviewing test assertions, doubles, or mocks. The loop and completion contract stay in the skill's `SKILL.md`.

## A good test

A good test states a capability the caller relies on and survives any refactor that keeps that capability:

- it exercises the public interface at an agreed seam;
- its name says what the caller gets, not how the code does it;
- it asserts one observable outcome;
- it fails only when behavior changes.

```ruby
# Good: behavior through the public interface.
def test_checkout_confirms_an_order_for_a_valid_cart
  cart = Cart.new
  cart.add(product, quantity: 2)

  order = Checkout.new(gateway: FakeGateway.new).call(cart)

  assert_predicate order, :confirmed?
end
```

## Implementation-coupled tests

These break on a refactor that changes no behavior. Warning signs:

- doubling your own collaborators;
- calling private methods with `send`;
- asserting call counts or call order;
- a name that describes how, not what;
- verifying through a side channel instead of the interface.

```ruby
# Bad: pins an internal collaborator call.
def test_checkout_calls_the_pricing_calculator
  calculator = Minitest::Mock.new
  calculator.expect(:total_for, 2_000, [Cart])
  Checkout.new(gateway: FakeGateway.new, calculator: calculator).call(cart)
  calculator.verify
end

# Bad: verifies through the database instead of the interface.
def test_register_saves_a_row
  Registration.new.call(email: "a@example.com")
  assert Account.connection.select_value("SELECT 1 FROM accounts WHERE email = 'a@example.com'")
end

# Good: verifies through the interface the caller uses.
def test_registered_account_can_be_found_by_email
  account = Registration.new.call(email: "a@example.com")
  assert_equal account, Account.find_by_email("a@example.com")
end
```

A model or request test that reads the record back through the application's own finder is using the interface. A raw SQL check of the row is a side channel unless the persisted shape is itself the contract, as with a migration or a database constraint.

## Tautological tests

The expected value is computed the same way the code computes it, so the test passes by construction.

```ruby
# Bad: recomputes the implementation.
def test_total_sums_line_items
  items = [LineItem.new(price_cents: 1_000), LineItem.new(price_cents: 500)]
  assert_equal items.sum(&:price_cents), Invoice.new(items).total_cents
end

# Good: an independent, known literal.
def test_total_sums_line_items
  items = [LineItem.new(price_cents: 1_000), LineItem.new(price_cents: 500)]
  assert_equal 1_500, Invoice.new(items).total_cents
end
```

The same trap appears as a snapshot generated by the code under test and never checked by hand, or a constant asserted equal to itself.

## When to use a double

Double at system boundaries you do not control:

- external HTTP APIs, payment, mail, and SMS providers;
- time and randomness (`travel_to`, an injected `Random`);
- the file system or process environment, sometimes;
- the database only when the repository deliberately avoids it; prefer the test database.

Use the real object for anything the repository owns: models, POROs, services, and internal collaborators.

With RSpec, use verifying doubles (`instance_double`, `class_double`) so a double cannot drift from the real interface. With Minitest, prefer a small hand-written fake that implements the same public methods.

## Designing for doubles

Make the boundary easy to replace:

- **Inject the external collaborator** instead of constructing it inside:

  ```ruby
  class Checkout
    def initialize(gateway: PaymentGateway.new)
      @gateway = gateway
    end
  end
  ```

- **Give each external operation its own method** instead of one generic request method, so each fake returns one known shape and the test shows which operations it relies on:

  ```ruby
  class ShippingClient
    def quote(parcel) = get("/quotes", parcel.to_h)
    def book(quote_id) = post("/bookings", quote_id: quote_id)
  end
  ```
