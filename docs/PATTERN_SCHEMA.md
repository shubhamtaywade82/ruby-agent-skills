# Pattern Schema

Patterns are reusable implementation guidance, not skills.

Recommended structure:

~~~markdown
---
name: service-object
description: Use when a coherent workflow spans multiple responsibilities...
family: ruby-design
---

# Service Object

## Problem

## Use when

## Do not use when

## Repository inspection

## Structure

## Implementation procedure

## Example

## Failure modes

## Testing

## Review checklist

## Related skills
~~~

## Rules

- Keep the pattern narrower than a skill.
- Do not assume a pattern is appropriate merely because it exists.
- Prefer repository conventions over the example shown here.
- Examples should demonstrate structure, not dictate naming.
- Do not introduce abstractions solely to match a pattern.
- Keep framework/version-sensitive details explicit.
- Every pattern must include testing and failure guidance.
