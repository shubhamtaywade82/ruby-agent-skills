This release covers Iterations 159–176 (see `CHANGELOG.md`). It is the first release to ship the betterspecs.org audit pattern, the Rails Way audit pattern, and the wiring that connects the Rails Way pattern to the `rails-architecture` skill.

### RSpec betterspecs.org audit (Iteration 159)

`patterns/testing/rspec-betterspecs-audit.md` maps all 19 betterspecs.org guidelines to their existing enforcement points in this pack: `rubocop-rspec` cops, the `patterns/testing/rspec-*.md` pattern family, `skills/rails-test-engineering/references/rspec.md` rules, and the `evals/test-engineering/rspec-request-contract.yml` cases. Twelve rules are executable, three are partial, three are out of scope, and one is enforced by the eval contract. The pattern explicitly references Iteration 153's coverage of betterspecs #1 (describe naming), #4 (`:aggregate_failures`), and #18 (WebMock/VCR) so the cross-reference is consistent with the upstream RSpec reference content.

### The Rails Way audit pattern (Iteration 175)

`patterns/rails/the-rails-way.md` maps the Rails Way philosophy — convention over configuration, DRY, MVC, and use-Rails-before-reinventing-it — to its existing enforcement points across the pack. The pattern frames the philosophy as a 5-step decision hierarchy for AI coding assistants:

1. Follow the convention.
2. Assign responsibilities correctly.
3. Protect correctness and security.
4. Verify behavior.
5. Deviate deliberately.

Stop at the first step that resolves the decision; descend only when the previous step cannot answer. The pattern also includes a "where code belongs" placement table (eight concerns mapped to their default Rails home and owning skill) and an anti-pattern table (eight approaches that are NOT the Rails Way, each mapped to the existing skill or pattern that catches the violation — e.g. callback-as-orchestration → `rails-active-record` critical invariant; repository-around-Active-Record → `stack-minimality-review`).

### Wiring the Rails Way pattern into `rails-architecture` (Iteration 176)

`skills/rails-architecture/SKILL.md` now has a `## Patterns` table that lists the five patterns the skill consults (`request-flow`, `dependency-direction-contract`, `controller-service-authorization-composition`, `policy-object-boundary`, and `the-rails-way`), each with a "Load when" trigger and a coverage summary. The pattern names are load-bearing — in a single-skill install, the catalog is not present, so an agent names the pattern to load rather than linking to its path. `test/rails_architecture_system_test.rb` adds five regression assertions covering the new pattern: required artifact paths; the 5-step decision hierarchy strings; the eight anti-pattern anchor strings; manifest registration under the `rails` family; and the `rails-architecture` → `the-rails-way` pointer.

### Installing from this release

Pin to the release tag for reproducible environments:

    bash bin/install --ref v1.4.0 --agent claude

Or download the offline archive:

    curl -LO https://github.com/shubhamtaywade82/ruby-agent-skills/releases/download/v1.4.0/ruby-agent-skills-v1.4.0.tar.gz
    tar xzf ruby-agent-skills-v1.4.0.tar.gz
    cd ruby-agent-skills-v1.4.0
    bash bin/install --agent claude

After installing, verify the pack in place:

    ruby bin/skill-pack-verify --root ~/.claude/skills
    ruby bin/skill-pack-doctor --root ~/.claude/skills

Both tools ship in the archive; neither requires the source repository.
