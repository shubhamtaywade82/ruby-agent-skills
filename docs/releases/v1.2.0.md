This release covers Iterations 134–156 (see `CHANGELOG.md`). The entries below need action from upgrading users.

### Deprecated: standalone React and TypeScript skills

Standalone frontend engineering has moved to the separate [react-agent-skills](https://github.com/shubhamtaywade82/react-agent-skills) pack. These skills still ship in this release, marked `DEPRECATED` in their descriptions. Use them only to maintain existing work. They will be removed in a later release.

| Deprecated skill | Replacement in react-agent-skills |
| --- | --- |
| typescript-core-engineering | typescript-core-engineering |
| typescript-type-design | typescript-type-design |
| typescript-runtime-contracts | typescript-runtime-contracts |
| react-component-engineering | react-component-engineering |
| react-state-effects | react-hooks-effects + react-state-management |
| react-data-fetching | react-data-fetching |
| react-testing-engineering | react-testing-engineering + frontend-e2e |
| react-accessibility-performance | react-accessibility + react-performance |
| react-architecture | react-architecture |

When a later release removes them, `bin/install` deletes them from existing installations and prints where each one moved. Install `react-agent-skills` alongside this pack if you need them.

### Kept: the Rails side of Rails ↔ React

`rails-react-integration` stays in this pack and is now in the `rails` family.
- Its five patterns moved from `patterns/react-typescript/` to `patterns/rails/`.
- Its evaluation moved to `evals/rails-react-integration/`.
- The skill now documents which pack owns each side of a full-stack change.

### New verification rules

Owning skills now require:
- a failing query-count test before N+1 fixes;
- rerunnable engine install generators;
- no-JavaScript Hotwire baselines;
- characterization tests before refactors;
- rerunnable seeds with no secrets;
- tested authorization denial.

`change-review` flags a fixed list of security patterns as always critical. GraphQL (graphql-ruby) work is now covered by `rails-api-integration`.

### Other changes that affect users

- `bin/coding-agent-claude` and `bin/routing-agent-claude` require `CLAUDE_MODEL`; there is no default model.
- The public routing campaign is now version 7 with 25 cases. The frontend-only `react-filter-render-performance` case was removed, so results from earlier campaign versions are not directly comparable.
- Framework-drift detection now matches real code; earlier registry regexes could not match anything. It also flags Ruby 3.2 removals.
