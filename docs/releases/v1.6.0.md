This release covers Iterations 195–200 (see `CHANGELOG.md`) plus three follow-up PRs landed directly on `main` after Iteration 200 (#117 MCP HTTP fallback and endpoint trust, #118 CI RuboCop line-length fix, #119 MCP ecosystem expansion to 25+ companion tools). It is the release that ships the autonomous engineering platform, the cross-pack v3 manifest and the pack's own MCP server, the Ruby/Rails MCP developer tool reference, the MCP permission profiles and preflight server, and the expanded companion-MCP ecosystem catalogue.

### Autonomous Engineering Platform (Iterations 195–197)

Three iterations land the bounded-autonomy platform documented in `patterns/rails/autonomous-engineering-platform.md`:

1. **Batch 1 — Foundation and Governance** (Iteration 195) adds CODEOWNERS, Dependabot, the security workflow, least-privilege `permissions:` blocks on every workflow, and `scripts/audit_github_governance.rb` with the first five governance checks.
2. **Batch 2 — Production-grade CI** (Iteration 196) extracts the shared Ruby CI shape into `.github/workflows/reusable-ruby-ci.yml` (reusable via `on: workflow_call`) and refactors `validate.yml` to call it. The governance audit gains Check 6 (every `reusable-*.yml` must declare `on: workflow_call`).
3. **Batch 3 — Agentic Engineering** (Iteration 197) ships the three gated agent workflows (`agent-issue-triage`, `agent-ci-investigator`, `agent-pr-reviewer`) and the single bounded dispatcher `scripts/agent_dispatch.rb`. The CI investigator is **propose-only** (it posts diagnosis + proposed patch as a comment, never pushes a branch or opens a PR); the PR reviewer is **advisory-only** (it comments, never approves). The governance audit gains Check 7 (every `agent-*.yml` must declare `timeout-minutes:`, must gate on a `vars.X`/`secrets.X` flag, and must not contain an approval command). Every workflow fails safe: with the gating variable unset, it exits 0 with a skip message rather than running.

To activate the agents in a real repository: set the `AGENT_COMMAND` secret to the agent CLI invocation, set `vars.AGENT_ISSUE_TRIAGE_ENABLED` / `AGENT_CI_INVESTIGATOR_ENABLED` / `vars.AGENT_PR_REVIEWER_ENABLED` to `'true'`. Leave any unset and that workflow skips.

### Cross-Pack v3 Integration and pack MCP server (Iteration 198)

Adds the cross-pack manifest schema v3 as an additive superset of v2 (existing v2 consumers see no change): top-level `schema_version: 3`, a `pack:` envelope, optional per-skill `version`/`language`/`category`/`companion_owners` fields, and a `cross_pack:` section declaring companions, name collisions, and seam contracts. Declares two companions: `node-agent-skills` (new snapshot, zero documented name collisions by design — the node pack prefixes every skill with `node-`) and `react-agent-skills` (eight documented collisions registered with explicit `companion_wins`/`context_dependent` resolutions).

Adds the `rails-node-integration` seam skill owning the Rails side of the Rails ↔ Node backend boundary, the `rails-node-backend-seam` pattern (453rd pattern), and `bin/cross-pack-verify` (stdlib-only Ruby, RuboCop-clean).

Adds the pack's own MCP server (`bin/mcp-server` + `lib/ruby_agent_skills/mcp_server/` — stdlib-only JSON-RPC 2.0 over stdio) mirroring the companion node pack's tool surface: `list_skills`, `get_skill`, `route_prompt` (with `file` language boosting), `list_companions`, and `route_cross_pack`. Honors `RUBY_AGENT_SKILLS_ROOT`. Also adds `CLAUDE.md` at the repository root so Claude Code sessions auto-load the engineering contract, and `docs/CLAUDE_CODE_INTEGRATION.md` for the wiring details.

### MCP Permission Profiles and Server Preflight (Iteration 200)

Adds `mcp/permissions.yml` with explicit server/tool-to-capability mappings and five base permission profiles: `inspect`, `test`, `debug`, `console`, and `maintenance`. Unknown tools and production are denied; production access and credential export are unconditional hard denies; execution, debugger, shell, and write capabilities require an isolated-environment attestation; sensitive actions require approval. Adds `bin/mcp-preflight` and the stdlib `RubyAgentSkills::MCPPreflight` implementation. The preflight reads a consuming MCP client's `mcpServers` JSON configuration, checks local policy before process/network activity, and requires explicit `--probe` before starting a configured STDIO command or contacting Streamable HTTP. Modern MCP `2026-07-28` discovery and `tools/list` probing, with legacy `2025-11-25` initialize fallback over STDIO and same-endpoint HTTP. The preflight never invokes `tools/call`.

Adds `skills/agent-workflow/references/mcp-governance-and-preflight.md` linked from `agent-workflow`, the Ruby/Rails MCP tools guide, the routing matrix, the README, and the Claude Code integration guide. Documents that `--isolated` is an operator attestation and that the preflight is not a reference monitor — the MCP host/application must enforce actual approval and authorization.

### MCP HTTP fallback and endpoint trust (#117)

Documents the MCP HTTP destination and egress trust boundary, splits the legacy HTTP+SSE transport handling from the modern Streamable HTTP path, and rejects ambiguous MCP server transport registrations. The discovery layer now reports configuration state, transport health, authorization-required/unavailable states, and exact tool inventory separately. Normalized legacy and modern HTTP MCP tool names so the inventory is stable across both discovery protocols.

Wraps a long `assert_includes` in `test/ruby_rails_mcp_tools_reference_system_test.rb` to satisfy RuboCop `Layout/LineLength` (max 100). The Validate pipeline was failing on `main` because of this line; this PR returns the pipeline to green.

### Expanded companion-MCP ecosystem (#119)

Expands the Ruby/Rails MCP developer-tool reference (`skills/agent-workflow/references/ruby-rails-mcp-tools.md`) with a new `## Companion MCP ecosystem` section covering 25+ companion MCP servers and skills packs: rails-ai-context, rails-ai-bridge, active_mcp, rails-ai-agents, mcp_on_ruby, coatepec, Task Completion Verifier MCP, 37signals-skills, rails-skills, majestic-rails, rails-cto, superpowers-ruby, Postgres MCP Pro, DevDb, ruby-postgres-mcp-server, Context7, Playwright MCP, GitHub MCP, Sentry MCP, Sequential Thinking, web-dev-mcp-gateway, the official Ruby MCP SDK, fast-mcp, ruby_llm-mcp, mcp_rails_template, and hitch-rails. Each entry has best-for, install, and scope-and-security; an install-scope table; security-contract items covering database administration, browser automation, version-control writes, error-monitoring reads, and external context; a skill-composition table; and a recommended seven-layer agent-native stack.

Extends the MCP permission vocabulary with four new capability classes (`database_admin`, `browser_automation`, `version_control`, `external_context` — each with their read/write split) and four new permission profiles. Adds starter tool classifications in `mcp/permissions.yml` for postgres-mcp-pro, devdb, ruby-postgres-mcp-server, playwright, web-dev-mcp-gateway, github, sentry, context7, and sequential-thinking. Adds `capability_aliases` so a tool can be classified under a short name that resolves to the full capability.

Adds `test/ruby_rails_mcp_companion_ecosystem_system_test.rb` (15 tests / 144 assertions) registered in `bin/validate` to assert every listed tool appears in the reference, the new capability vocabulary, the new profiles, and the permissions policy classifications. The test file includes a self-check that `bin/validate` runs it. Updates `skills/agent-workflow/SKILL.md` and `router/ROUTING.md` to reference the expanded ecosystem.
